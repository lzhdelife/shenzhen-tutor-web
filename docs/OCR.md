# Windows 微信 OCR 助手

## 能做什么

`TutorOrderWatcher` 从当前可见的电脑版微信聊天区域读取文字，自动整理连续多屏订单并上传网站。它适用于个人微信没有合规群聊历史 API 的场景。

它不能：

- 读取未显示或已经删除的聊天记录。
- 在微信最小化且无法恢复时后台读取。
- 保证识别所有图片、视频、语音和小程序卡片内容。
- 绕过微信权限或直接访问微信数据库。

## 窗口和 DPI 定位

启动时脚本依次尝试 Per-Monitor V2、Per-Monitor 和 System DPI aware。随后寻找进程名为 `WeChat` 或 `Weixin`、主窗口不小于 500x400 的最大可见窗口。

自动正文矩形按物理窗口比例计算：

- 左边界约为窗口宽度的 48%。
- 顶部约为窗口高度的 7%。
- 宽度约为窗口宽度的 50%。
- 高度约为窗口高度的 76%。

这个规则针对当前电脑版微信布局和 200% 缩放调过，但不是微信官方稳定接口。微信 UI 改版后应首先更新 `Get-WeChatChatBodyRect`，并在 100%/200% 和多显示器环境重新验证。

## OCR 选择

1. `WindowsOcr.ps1` 初始化 `Windows.Media.Ocr.OcrEngine` 的简体中文语言。
2. Windows OCR 是首选，因为中文行结构通常更稳定。
3. 当质量分不足或检测到结构化字段需要交叉核实时，调用 Tesseract。
4. Tesseract 可使用普通页面、稀疏文字或增强图片模式。
5. `Merge-PreferredOcrText` 只从备用结果补充价格、时间、地点等高价值行，减少两套结果互相污染。
6. `Clean-OcrText` 删除微信 UI 噪声、未读消息计数、时间戳和常见乱码，并修正常见 OCR 字形错误。

OCR 质量是规则评分，不是机器学习置信度。新增清洗规则时要防止把真实地名、编号和课酬删掉。

## 群聊自动切换

自动切群流程：

1. 激活微信，发送 `Ctrl+F`。
2. 粘贴群名关键词。
3. 用 UI Automation 查找“查看全部”并真实点击。
4. 枚举左侧搜索结果中的 `ListItem`，按规范化群名去重。
5. 滚动完整结果列表，打开第 N 个唯一结果。
6. 保存成功读取群名和时间，界面以红/绿状态显示。

已知脆弱点：微信可能虚拟化未显示的结果项；同名群在规范化后无法区分；“查看全部”控件名或布局变化会破坏选择。

## 跨屏处理

- 每次向上滚动约半屏，而不是整屏，确保长订单在相邻截图中重叠。
- 所有屏先识别，最后统一调用 `Merge-OcrPages`，不会逐屏直接发布。
- 相邻屏会额外生成接缝图，全部屏会生成纵向合成图。
- 网站按每条订单文本与每个页面 OCR 的相似度选择最佳原图，只保存一张。
- 缺少地点、年级、科目或关键结构的半条订单会暂缓；下一屏补齐后再上传。

## 上传协议

助手先调用 `/api/login` 取得中介 Bearer Token，然后调用 `/api/import`。图片使用 `data:image/png;base64,...`，因此多屏读取会显著增加请求大小。网站当前请求上限约 30 MiB。

密码只存在当前 GUI 文本框和进程内 Token 中，不写入 `config.json`。其他配置会保存，包括高德 Key 和手机号，因此 `TutorOrderWatcher/data/` 仍是敏感目录。

## 停止机制

长等待通过 `Wait-Responsive` 分成短间隔，持续处理 WinForms 消息并检查 `$Script:StopRequested`。停止按钮会先停止计时器，再让当前 OCR、网络请求或 UI 步骤在检查点退出。外部 OCR/HTTP 调用仍可能等待各自超时后才完全停止。

## 准确率评估建议

不要只统计“新增了多少条”。建议对匿名基准集分别记录：

- 订单拆分召回率和精确率。
- 地点、年级、科目、价格、时间、教师性别逐字段准确率。
- 半条订单误发布率。
- 重复订单率。
- 原图对应正确率。
- 每屏耗时和停止响应时间。

测试素材必须先匿名化。精确住宅、手机号、群名、头像和微信昵称均应移除或替换。
